{% comment %} Today's shifts, grouped by kind -- the whole point of the kitchen tablet (P2 design doc §5/§7). Shared by koekken/idag.html and the htmx swap after a mark-done POST (koekken.views._tablet_context), so the tablet's list can never disagree with what a tap just did. A closed/out-of-window mark-done button is REMOVED, not disabled (§10) -- `can_mark` decides per row, and a row whose window has not opened yet, or has already closed, or is already udført/anmeldt/ikke udført, simply has no button and no POST target at all. Deliberately no `id` on this root: it is swapped with `hx-swap="innerHTML"` INTO the persistent `#idag-vagter` wrapper in idag.html, not swapped itself with `outerHTML` -- so that wrapper node survives every swap and `frontend/src/koekken.ts`'s delegated submit listener on it never goes stale (an outerHTML swap would replace the very node the listener is bound to). F1: `yesterday_rows` -- shifts from yesterday still inside their own marking window (the window runs through the end of the day AFTER the shift, per §5), so filtering to today alone made half that window unreachable at the tablet. Rendered in its OWN labelled section ("I går") rather than folded silently into today's grid, so residents are never confused about which day a row is actually for. `rows` keeps its original shape/key so this partial renders identically to before when `yesterday_rows` is absent (e.g. the existing §10 button test, which only ever passes `rows`). {% endcomment %} {% if yesterday_rows %}
