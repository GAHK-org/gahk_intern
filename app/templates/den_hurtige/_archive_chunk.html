PREPENDED, NEVER APPENDED. The sentinel sits at the TOP of the feed's scroll region and replaces itself with this (hx-swap="outerHTML"), so what lands here goes above everything already on screen: first the next sentinel, then this chunk's messages, then the messages that were there before. That ordering is what keeps the whole column reading downwards into the live feed. It also means the reader's scroll position has to be corrected for the height that just arrived above the viewport, or the conversation jumps under their thumb. frontend/src/feed.ts does that on htmx:afterSwap — Safari has no scroll anchoring, so it cannot be left to the browser. Self-contained on purpose: this is inserted into a live page, so anything it needs must be in here. Nothing outside it is re-rendered. {% endcomment %} {% comment %} `paged` is set by the standalone page, which walks the chunks with plain links below the messages instead. NO hx-target, deliberately. hx-target inherits in htmx, and the feed above declares none for exactly this reason (see feed.html); left alone it defaults to itself, which is what a self-replacing sentinel wants. NOT `revealed`, WHICH DOES NOT WORK HERE. htmx implements `revealed` with a scroll listener on the window plus a "is it in the viewport" test, and scroll events do not reach the window from an inner overflow container — #js-feed is the thing that scrolls, not the document. The symptom is the worst kind: it fires once on load (the initial check) and then never again, so the archive looks like it works and simply stops after one chunk. `intersect` uses an IntersectionObserver instead, and `root:#js-feed` points it at the box that actually moves. `once` because this element is consumed by the swap anyway; it stops a second observation firing a duplicate request while the first is still in flight. {% endcomment %}
