This used to be a flat grid: avatar, then a header line carrying the name, the time and the expiry, then the text. It read as a forum, and it broke down precisely on the case a chat has most of — the same person writing twice. A continuation dropped the name but KEPT the header, so every follow-up carried a stray "14:32 · ⏱ 45 min" line above it with no name attached; and two of your own messages in a row drew two separate green rounded boxes 1px apart, which read as one torn box rather than two messages. Bubbles fix both by construction: the meta moves down INTO the bubble, trailing the last line of text where it costs no height at all, and a run of bubbles squares off its own inner corners into one shape. Modelled on Messenger rather than Slack, deliberately: Den Hurtige replaces the house's Messenger group (see the module docstring in views.py), so that is the layout residents already read fluently. It is what puts the name on the FIRST bubble of a run and the avatar and tail on the LAST — the name introduces the run, the avatar sits beside where it ends. Own messages get no avatar at all: right-alignment already says who wrote it, and the 34px column it would cost is width a phone has none to spare. Two structural rules are load-bearing rather than cosmetic: * .msg-line exists ONLY to put the avatar on the same flex line as the bubble, so `align-items:flex-end` lands it beside the bubble's bottom edge. Aligning against .msg as a whole would measure to the bottom of the action row instead and leave the avatar sitting next to the reaction pills, a row too low. * .msg-actions is OUTSIDE .msg-bubble. The reaction pills are a wide wrapping strip, and inside a coloured bubble they made every bubble as wide as its widest row of pills — the text no longer set the width. It also keeps the row's `.pop` pickers out of the bubble's subtree, which matters for the shape of the swipe transform (see .msg in styles.css). {% endcomment %} {% comment %} data-msg-swipe marks this as a swipe target for frontend/src/feed.ts: right opens the thread, left (own messages) submits the delete form.
